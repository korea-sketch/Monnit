# Monnit Korea — Modbus 구성 제안 랜딩 + 제안서

`https://monnit.co.kr/promo/modbus/` 에 올라가는 랜딩페이지와, 그 페이지에서 발급하는
기술 제안서(43p PDF)의 소스입니다.

## 페이지 구성

이 자료의 논지는 세 단계이고, 이 순서가 전부입니다.

1. **왜 계측인가** — AI · AX · 자동화는 우리 설비에서 나온 데이터 위에서만 돌아갑니다.
   계측 → 축적 → 보유 → 활용. 이 순서는 건너뛸 수 없고, AI가 막히는 지점은 대개 알고리즘이 아니라 *입력이 빈 것*입니다.
   계측점을 막아 온 것은 배선이었고, 무선이면 그 제약이 사라지면서 **비용 구조도 달라집니다.**
2. **왜 Monnit인가** — 무선을 관제에 넣을 때 무서운 건 정확도가 아니라 *가끔 값이 비는 것*입니다.
   끊김 · 데이터 보존 · 센서 자기 진단, 이 셋이 갖춰져야 상위 시스템에 넣을 수 있습니다.
3. **그래서 이런 구성이 가능하다** — Modbus로 붙이는 현장 유형별 구성안 4종.

매뉴얼이 아닙니다. 설정 절차와 문제 해결은 필요한 사람만 보도록 부록으로 내렸습니다.

| # | 섹션 | 하는 일 |
| --- | --- | --- |
| 1 | **왜 계측인가** | 계측 → 축적 → 보유 → 활용 4단계 + 설치 제약 + 비용 구조 |
| 2 | **왜 Monnit인가** | 무선을 관제에 넣기 위한 5가지 요건과 Monnit의 해법 |
| 3 | **구성 제안 4종** | 현장 전제 · 센서 수량 · 점유 주소 · 남는 데이터 |
| 4 | 추가되는 것은 게이트웨이 한 대 | 유선/무선 도식 + 구성도 + 근거 4개 + 게이트웨이 2종 |
| 5 | 붙이는 절차 | 4단계 + 레지스터 도식 (상세는 제안서 부록) |
| 6 | 제안서 다운로드 | 목차 + 신청 폼 (제출 즉시 PDF 전달) |
| 7 | 현장 구성 검토 | 알려주실 5가지 + 요청 양식 |

각 구성안에는 **「이 구성이 남기는 데이터」** 절이 들어 있습니다.
그 구성으로 1년을 돌리면 어떤 데이터 자산이 쌓이고, 그것이 왜 AI·분석의 출발점이 되는지를 적었습니다.

### 1장에서 쓰는 근거

모두 monnit.co.kr 또는 제품 자료에 이미 실려 있는 값만 씁니다.

| 요건 | Monnit의 해법 |
| --- | --- |
| 끊기지 않는 무선 | 900MHz FHSS 주파수 도약 |
| 거리 · 관통력 | 비가시 벽 12장 관통 1,200ft 이상 (XL은 벽 18장 2,000ft 이상) |
| 끊겨도 남는 데이터 | 센서 자체 최대 4,000건 저장, 복구 시 누락 없이 전송 |
| 센서 자기 진단 | 슬롯 16 레지스터 중 앞 8개가 상태 정보 |
| 전원 | AA 기준 최대 10년, 잔량이 레지스터로 노출 |
| 보안 | Encrypt-RF (256-bit 키 교환 + AES-128) |

각 구성안은 같은 틀입니다 — 상위 시스템 / 현장 전제 / 센서 구성표 / 슬롯·주소 / 얻는 것.
**센서 수량과 점유 주소를 실제 숫자로** 적어, 그대로 견적 요청이나 품의 근거로 쓸 수 있게 했습니다.

산업 네 곳은 **이미 현장에 Modbus 마스터(PLC·BMS·SCADA)가 돌아가고 있는 곳**만 골랐습니다.

### 구성안 요약

| 구성안 | 상위 시스템 | 센서 | 점유 레지스터 | 주소 |
| --- | --- | --- | --- | --- |
| ① 공장 · 제조 (05장) | PLC · SCADA | 20대 | 320 | 40101 – 40420 |
| ② 데이터센터 · IDC (06장) | DCIM · BMS | 48대 | 768 | 40101 – 40868 |
| ③ 대형 건물 · FM (07장) | BMS | 26대 | 416 | 40101 – 40516 |
| ④ 에너지 · 인프라 (08장) | SCADA · RTU | 24대 | 384 | 40101 – 40484 |

주소는 `40101 + 16 × (N − 1)` 로 계산한 값이며, 수량을 바꾸면 다시 계산해야 합니다.

## 백서를 어떻게 내려주는가

두 가지 방식을 모두 지원하며, **설정 없이 그대로 올려도 동작합니다.**

| DOC_API | 동작 |
| --- | --- |
| 비어 있음 (기본) | 같은 폴더에 올려 둔 PDF를 신청 폼 제출 직후 바로 내려받게 합니다 |
| 값이 있음 | 발급 API가 만들어 준 1회용 URL로 내려받습니다 |

발급 API를 쓰시려면 `landing/landing_template.html` 맨 아래 스크립트의
`DOC_API` 와 `DOC_TOKEN` 에 현재 운영 페이지의 값을 옮겨 넣으십시오.
어느 쪽으로 빌드됐는지는 빌드 마지막 줄에 표시됩니다.

## 디자인

흰 바탕에 큰 타입과 넓은 여백을 쓰고, **테두리 대신 면과 간격으로 구분**합니다.
모든 값은 `landing/theme.css` 한 곳에 있습니다.

| 항목 | 값 |
| --- | --- |
| 본문 폰트 | Pretendard Variable (jsDelivr) — Apple SD Gothic Neo 대체용 |
| 수치·주소 | IBM Plex Mono |
| 브랜드 색 | `#1168AD` (로고에서 추출) |
| 면 | 흰색 / `#f5f5f7` 교차, 히어로·푸터만 `#0b0d12` |
| 모서리 | 카드 20px, 버튼 완전 둥근 형태 |
| 모션 | IntersectionObserver 페이드업, `prefers-reduced-motion` 존중 |

히어로와 푸터는 어둡고 본문은 밝습니다. 제품 사진이 흰 배경에서 촬영된 것이라
밝은 면에서 훨씬 자연스럽고, 기술 문서 성격에도 밝은 쪽이 맞습니다.

색을 바꾸려면 `theme.css` 상단 `:root` 의 변수만 고치면 전체에 반영됩니다.

## 제품 사진

히어로와 게이트웨이 선택 카드는 **실제 제품 사진**을 씁니다.
`Monnit Component` 폴더의 원본을 `landing/assets/product/` 로 가져와, 투명 배경을 살린 채
표시 크기의 2배로 줄여 두었습니다. AI로 만든 광고 이미지는 라벨 글씨가 깨져 있어
페이지 본문에서는 걷어냈고, OG 미리보기 이미지 생성에만 남겨 두었습니다.

| 파일 | 쓰이는 곳 | 원본 |
| --- | --- | --- |
| `hero-products.png` | 히어로 | 온습도 + 누수 + 진동 센서 3종 합성 |
| `sensor-th.png` / `sensor-water.png` / `sensor-vib.png` | 합성 소스 | 제품사진 / ALTA Industrial · AA |
| `logo-monnit.png` | 백서 표지 | Brand logos / Monnit_Blue |

**게이트웨이 사진은 넣지 않았습니다.** 컴포넌트 폴더에 있는 게이트웨이 이미지는
`Monnit-Unbranded-*` 계열(OEM용 무각인 제품)뿐이라 실제 판매 제품과 다릅니다.
`ALTA-Gateways` 폴더에도 USB Pro만 있습니다. 이더넷·시리얼 게이트웨이 실사진이 확보되면
`게이트웨이 선택` 카드에 바로 넣을 수 있도록 자리를 비워 두었습니다.

원본 PNG는 가장자리 안티에일리어싱이 흰색이라, 어두운 배경에 그대로 올리면 흰 테두리가 보입니다.
`sensor-*.png` 와 게이트웨이 파일은 투명 영역의 RGB를 눌러 이 현상을 제거한 상태입니다.
**사진을 교체하실 때는 같은 처리를 하거나, 밝은 배경에서만 쓰십시오.**

## 도식

`landing/diagrams.py` 가 SVG 도식 3종을 만들어 랜딩과 백서 양쪽에 넣습니다.
같은 도식을 랜딩은 어두운 팔레트로, 백서는 인쇄용 팔레트로 그립니다.

| 도식 | 랜딩 | 백서 |
| --- | --- | --- |
| 계측점 1개를 늘릴 때 (유선 6단계 vs 무선 3단계) | 게이트웨이 섹션 | 그림 1-1 |
| 슬롯이 쌓이는 방식 (주소가 16씩) | 붙이는 절차 | 부록 A |
| 레지스터 16칸 구조 (앞 8 상태 / 뒤 8 측정) | 붙이는 절차 | 부록 A |

산업 블록 네 개의 아이콘도 여기서 만듭니다. 도식 문구를 고치려면 `diagrams.py` 를 수정한 뒤

```bash
cd landing
python3 diagrams.py    # 템플릿과 백서에 SVG 재삽입
python3 build.py       # 랜딩 재빌드
```

사진은 이 스크립트가 건드리지 않습니다.

## 랜딩페이지 빌드

```bash
cd landing
python3 diagrams.py   # 도식을 고쳤을 때만
python3 build.py
```

이미지를 base64로 인라인하고 `<head>`의 OG 태그를 채워 `dist/modbus_landing.html` 을 만듭니다.
결과는 약 0.8MB입니다. **PDF는 HTML과 같은 폴더에 반드시 함께 올려야** 다운로드가 됩니다.

GA4와 Meta Pixel은 **사이트 전역 GTM에서 이미 처리되고 있어** 빌드에서 삽입하지 않습니다.
이 페이지에서만 따로 넣어야 할 일이 생기면 `build.py` 상단의 `GA4_ID` / `META_PIXEL_ID` 를 채우십시오.
(둘 다 채우면 GTM과 중복 집계됩니다.)

| 이벤트 | 시점 | 파라미터 |

메타 광고의 전환 최적화는 `whitepaper_download` 를 기준으로 잡으십시오.

## 백서 빌드

WeasyPrint와 한글 폰트(Noto Sans CJK KR)가 필요합니다.

```bash
pip install weasyprint
cd whitepaper
weasyprint whitepaper.html "../dist/무선센서_Modbus_연동_백서_MonnitKorea.pdf"
```

`figs/`는 `whitepaper.html` 기준 상대 경로로 참조되므로 두 파일은 같은 디렉터리에 두어야 합니다.
백서를 다시 만들면 dist의 PDF가 갱신되므로, 서버에 올린 PDF도 함께 교체하십시오.
페이지 수가 바뀌면 랜딩의 `43페이지` 표기와 `build.py` 의 `OG_DESC` 도 같이 고쳐야 합니다.

## 문의 폼

기술지원 문의 폼은 서버로 아무것도 보내지 않습니다. 입력값을 브라우저 안에서 정리된 텍스트로
만들어 복사하거나 `mailto:` 로 여는 방식입니다. 앱 내 브라우저에서 클립보드가 막히는 경우를 대비해
`execCommand` 폴백을 넣어 두었습니다.

백서 신청 폼은 회사명·이름·이메일이 필수이고 동의 체크가 있어야 제출됩니다.
`window.MonnitLead` 가 있으면 리드로 기록되고, 그다음 백서가 내려갑니다.

## 인앱 브라우저

페이스북·인스타그램·카카오 앱 안의 브라우저로 들어온 경우에만 상단에
"다른 브라우저에서 열기" 안내 띠가 나타납니다. 그 환경에서 PDF 저장이 막히는 일이 있어서입니다.

## 수치 검증 메모

백서의 레지스터 값과 스케일은 실제 캡처 화면과 대조해 확정했습니다.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 슬롯 N 시작 주소 | `40101 + 16 × (N − 1)` | 제품 문서 (그림 4-2) |
| 온습도 Data1 / Data2 | 읽은 값 ÷ 100 | 2291 / 3955 → 22.91℃ / 39.55 %RH |
| 배터리 전압 | 읽은 값 ÷ 100 | 321 → 3.21V |
| 조도 | `(Data1 × 65536 + Data2) ÷ 100` | 0x58080 = 360576 → 3,605.76 Lux |
| Application ID | 온습도 43 · 누수 4 · 조도 107 · 모션플러스 138 · CO₂ 106 | 실측 화면 |

랜딩에 쓴 수치(256대 / 16 레지스터 / 80종+ 센서 / 최대 10년 배터리 / 1,200ft)는
모두 백서 또는 monnit.co.kr 본문에 이미 실려 있는 값만 사용했습니다.

백서 1장의 센서 종류 수는 원래 `55종+` 였는데, monnit.co.kr 현재 표기인 `80종+` 로 맞췄습니다.
두 문서가 함께 배포되므로 숫자가 달라서는 안 되기 때문인데, **어느 쪽이 맞는지 확인해 주십시오.**

### 비용 수치에 대하여

1장의 비용 비교(설치 15분 / 구축비 최대 1/30 / 점검 시간 −90% / 회수 6~12개월)는
**monnit.co.kr 홈페이지에 이미 공개된 값**을 그대로 옮긴 것입니다. 새로 만든 수치가 아닙니다.
다만 제안서와 랜딩에 함께 실리는 값이므로, **현재도 유효한 수치인지 확인해 주십시오.**

## 상표 · 공개 전 확인

제품 표기는 `MONNIT 무선센서`로 통일했습니다. 상표 고지 줄의 ALTA는 법적 문구라 그대로 두었습니다.

Monnit, iMonnit, ALTA, Encrypt-RF는 Monnit Corporation의 상표입니다.
화면 캡처에 담긴 IP · 센서 ID · 측정값은 캡처 당시의 실제 값이므로, 외부 공개 전에
공개해도 되는 정보인지 확인하시기 바랍니다.

백서에 아직 채우지 못한 항목은 `확인필요-백서보완.md` 에 정리해 두었습니다.
특히 **KC 인증·국내 주파수**와 **영하 온도 표현 방식**은 광고 유입 전에 정리하시길 권합니다.
