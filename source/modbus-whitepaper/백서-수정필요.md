# 백서에서 달라져야 하는 것

43페이지를 다시 훑고, **랜딩이 새로 약속한 것과 백서가 실제로 주는 것이 맞는지**를
기준으로 정리했습니다. 랜딩 첫 화면이 이제 「구성 산출 · Modbus 실측 검증 · 이상 시
진단 절차」를 내걸기 때문에, 그 세 지면(11p · 38p · 39p)이 사실상 간판입니다.

| | 항목 | 지면 | 상태 |
|---|---|---|---|
| 1 | 영하 온도(음수) 처리 | 25p · 39p | **비어 있음 — 발행 전 채우는 것을 권합니다** |
| 2 | KC 인증 · 국내 주파수 | 43p | **비어 있음 — 확인 필요** |
| 3 | 진동 센서 채널 표 | 29p | 비어 있음 — 구성안 ①의 간판 센서인데 읽는 법이 없습니다 |
| 4 | 폴링 주기 설계 기준 | (없음) | 비어 있음 — 문의로 자주 올 내용 |
| 5 | 비용 수치 | 랜딩 | 확인만 필요 |
| ✓ | 그림 7-4 참조 오류 | 40p | **고쳤습니다** |
| ✓ | 80종 / 80종+ 혼용 | 7p | **고쳤습니다** |

---

## 1. 영하 온도 — 가장 먼저 채워야 합니다

### 지금 상태

25p 온습도 센서 표에 이렇게만 적혀 있습니다.

| 채널 | 값 | 비고 |
|---|---|---|
| Data 1 (+8) | 온도 × 100 | 섭씨(℃)로만 제공됩니다 |

39~40p 증상표에도 「온도가 2291처럼 100배로 나옴 → 정상입니다, ÷100 하세요」만 있습니다.

### 왜 문제인가

**영하로 내려가는 순간 값이 65000 대로 튑니다.**

16비트 레지스터 한 칸에 −5.2℃를 담으면 −520이고, 이걸 부호 없는 정수로 읽으면
`65536 − 520 = 65016` 입니다. Modbus Poll 기본 표시도, 상당수 PLC의 기본 워드
타입도 **부호 없는 정수**입니다.

구성안 4종 중 **셋이 영하를 만납니다.**

- 구성안 ① 공장 — 옥외 판넬, 겨울 새벽
- 구성안 ③ 대형건물 — 지하 기계실 동파 감시가 목적
- 구성안 ④ 에너지·인프라 — 옥외가 기본

즉 **겨울에 가장 먼저 들어올 문의**인데, 백서 어디에도 답이 없습니다.
받은 사람은 센서가 고장 났다고 판단합니다.

### 제안하는 문안

먼저 **실측으로 확인해 주십시오.** 센서 하나를 냉동고나 얼음물에 20분 넣고
해당 레지스터를 읽으면 5분이면 끝납니다. 아래 둘 중 어느 쪽인지만 알려 주시면
문안을 확정하겠습니다.

- (A) 65016 처럼 큰 수로 보인다 → **부호 있는 16비트(2의 보수)** 입니다
- (B) −520 으로 바로 보인다 → 도구가 이미 부호 있는 정수로 읽고 있는 것입니다

**(A)일 경우 — 25p 표 아래에 넣을 문안**

> **영하 온도를 읽을 때**
> 온도 채널은 부호 있는 16비트 정수입니다. −5.2℃는 −520으로 실리는데,
> 부호 없는 정수로 읽으면 65016으로 보입니다. 값이 32768 이상이면
> 65536을 빼십시오.
>
> `온도(℃) = (값 ≥ 32768 ? 값 − 65536 : 값) ÷ 100`
>
> Modbus Poll에서는 해당 칸을 선택하고 오른쪽 클릭 → Format → **Signed** 로,
> PLC에서는 워드를 **INT(부호 있는 정수)** 로 받으면 변환 없이 그대로 읽힙니다.
> WORD·UINT로 받으면 겨울에만 값이 튑니다.

**39p 증상표에 추가할 한 줄**

| 증상 | 먼저 확인할 것 | 참조 |
|---|---|---|
| 겨울에만 온도가 65000 대로 나옴 | 영하값을 부호 없는 정수로 읽고 있습니다. 워드를 INT로 받거나 32768 이상일 때 65536을 빼십시오 | 부록 B · 온습도 센서 |

한 줄이지만 **이 줄 하나가 겨울 문의를 대부분 막습니다.** 그리고 39p는 이제
랜딩 첫 화면에 걸리는 지면입니다.

## 2. KC 인증 · 국내 주파수 — 확인만 해 주시면 됩니다

### 지금 상태

43p 사양표에 이렇게만 있습니다.

> 무선 방식 — 900MHz FHSS, 868 / 433MHz 대역 지원

### 왜 문제인가

**국내에서 무선 제품을 검토할 때 첫 질문이 이것입니다.**
전파법상 적합성평가(KC)를 받지 않은 무선기기는 국내에서 판매·설치할 수 없습니다.
공공기관·대기업 구매 절차에서는 인증번호를 문서로 요구합니다.

지금은 「900MHz」만 적혀 있어서, 꼼꼼한 담당자는 여기서 검토를 멈춥니다.
미국 대역(902~928MHz)과 국내 대역이 다르다는 것도 아는 사람은 압니다.

### 필요한 것

아래 세 가지를 알려 주시면 사양표에 넣겠습니다. 제가 확정할 수 없는 사실입니다.

1. **국내 판매 모델의 실제 동작 주파수** (국내 900MHz ISM 대역은 917~923.5MHz 입니다)
2. **KC 적합성평가 인증번호** — 게이트웨이와 센서 각각
3. **인증 주체** — 모넷코리아인지 Monnit Corporation인지

**들어갈 자리 (43p 사양표 맨 위)**

| 항목 | 사양 |
|---|---|
| 무선 방식 | 917~923.5MHz FHSS (국내 ISM 대역) |
| 적합성평가 | KC 인증 — 게이트웨이 R-R-○○○-○○○ / 센서 R-R-○○○-○○○ |

인증이 아직이라면 **그 사실을 적는 편이 낫습니다.** 「국내 인증 진행 중」이라고
써 두면 담당자가 일정을 물어보지, 그냥 덮지는 않습니다. 아무 말이 없으면 덮습니다.

## 3. 진동 센서 채널 표 — 간판 센서인데 읽는 법이 없습니다

### 지금 상태

29p에 이렇게 적혀 있습니다.

> 진동 계열(일반 진동, 정밀 진동, G-Force Max/Average), 기울기, 공기질 센서 역시
> 동일하게 슬롯 시작 주소 기준 +8부터 8개 채널에 측정값이 실립니다.
> **채널 구성이 모델마다 다르므로 해당 센서의 정의 문서를 기준으로 매핑합니다.**

### 왜 문제인가

**구성안 ① 공장·제조의 첫 줄이 「진동 · 표면 온도 12대」입니다.**
그리고 이 지면이 랜딩 첫 카드로 걸립니다.

온습도(25p)·누수(26p)·모션(27p)·조도(27p)는 채널 표가 다 있는데,
정작 제안서가 앞세우는 진동만 「정의 문서를 보십시오」로 끝납니다.
받은 사람 입장에서는 가장 궁금한 센서의 답이 없는 셈입니다.

### 필요한 것

국내에서 실제로 파는 진동 모델 **한두 종**의 Data 1~8 매핑만 있으면 됩니다.
전 모델을 다 채울 필요는 없습니다.

| 채널 | 값 | 비고 |
|---|---|---|
| Data 1 (+8) | ? | 예: X축 Velocity RMS × 100 |
| Data 2 (+9) | ? | |
| … | | |

제품 정의 문서나 Modbus Poll 실측 캡처 한 장을 주시면 제가 표로 만들고
39p 증상표에도 연결하겠습니다.

## 4. 폴링 주기 설계 기준 — 있으면 문의가 줄어듭니다

### 지금 없는 것

「PLC에서 몇 초마다 읽어야 하나」에 대한 답이 백서에 없습니다.

### 왜 필요한가

이건 **틀리면 조용히 손해를 보는** 항목입니다.

- 너무 자주 읽으면 — 값은 안 바뀌는데 통신만 돕니다. 센서 보고 주기보다
  빨리 읽어 봐야 같은 값만 나옵니다
- 너무 드물게 읽으면 — 센서는 보고했는데 PLC가 놓칩니다
- 센서 보고 주기를 짧게 잡으면 — 배터리 10년이 1~2년으로 줄어듭니다

마지막 항목이 특히 중요합니다. 백서가 「배터리 최대 10년」을 근거로 쓰는데,
그 수명이 **보고 주기에 달려 있다**는 설명이 없으면 나중에 말이 어긋납니다.

### 제안하는 자리

**부록 A 뒤에 반 페이지**, 또는 「도입 전 체크리스트」의 계측 계획 항목에 붙입니다.

필요한 숫자는 이 정도입니다.

- 센서 보고 주기 기본값 (분)
- 보고 주기별 배터리 수명 실측 또는 공칭치 (예: 10분 주기 → N년)
- 게이트웨이가 값을 보관하는 시간
- 권장 폴링 주기 = 센서 보고 주기의 몇 분의 1인지

랜딩과 백서가 함께 쓰는 숫자입니다. 모두 monnit.co.kr 공개 자료에서 가져왔고,
**지금도 유효한지만** 확인해 주십시오.

| 수치 | 쓰이는 곳 |
|---|---|
| 센서당 설치 15분 | 랜딩 비용 섹션 |
| 구축비 유선 대비 1/30 | 랜딩 비용 섹션 |
| 점검 시간 −90% | 랜딩 비용 섹션 |
| 투자 회수 6~12개월 | 랜딩 비용 섹션 |

숫자 자체보다 **출처 표기**가 중요합니다. 지금은 「모넷코리아 공개 자료 기준」으로
달아 두었는데, 실제 현장 데이터에서 나온 값이면 그렇게 쓰는 편이 훨씬 셉니다.

## 이미 고친 것

**그림 7-4 참조 오류 (40p)** — 기술지원 요청서의 「함께 보내 주시면 좋은 화면 캡처」
③번이 `(그림 D-2, 7-4 형태)`를 가리키고 있었습니다. 장 번호를 재정렬할 때 남은
옛 번호이고, **그림 7-4는 존재하지 않습니다.** `(그림 D-2 · D-5 형태)`로 고쳤습니다.
40p는 39p 바로 다음 장이라 랜딩에서 크게 보면 눈에 띄는 자리였습니다.

**80종 / 80종+ 혼용 (7p)** — 같은 문서 안에서 7p는 「80종」, 8p는 「80종+」였습니다.
`80종+`로 통일했습니다.

## 우선순위

발행 자체를 막는 것은 없습니다. 지금 그대로 올려도 됩니다.

다만 **1번(영하 온도)은 발행 전에 넣는 편이 좋습니다.** 5분 실측이면 확정되고,
안 넣으면 첫 추위에 문의가 몰립니다. 그리고 그 문의가 들어올 39p가 하필
랜딩 간판입니다.

**2번(KC)** 은 알려 주시는 즉시 반영하겠습니다. 국내 B2B에서는 이게 없으면
검토가 멈추는 경우가 실제로 있습니다.

3·4번은 자료를 주시면 다음 판에 넣겠습니다. 5번은 확인만 해 주십시오.
