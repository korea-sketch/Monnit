01왜 지금 무선센서 + Modbus인가

설비 데이터를 더 보고 싶다는 요구는 항상 있습니다. 막히는 지점은 대부분 센서가 아니라 배선과 상위 시스템 교체 비용입니다. 무선센서를 Modbus로 붙이면 이 두 가지를 모두 우회할 수 있습니다.

현장에서 반복되는 세 가지 벽

문제현장에서 벌어지는 일무선센서 + Modbus 연동 시
배선 비용과 공기 계측점 하나 추가에 배관·트레이·전원 공사가 따라붙고, 라인을 세워야 하는 구간은 아예 포기하게 됩니다. 센서는 배터리로 동작하고 게이트웨이까지 무선으로 전송합니다. 신규 배선은 게이트웨이 1대분만 필요합니다.
상위 시스템 교체 부담 새 모니터링 시스템을 별도로 도입하면 화면이 둘로 나뉘고, 운전원은 결국 기존 화면만 봅니다. 기존 PLC · BMS · SCADA가 Modbus 마스터로 값을 읽어갑니다. 화면 · 알람 · 이력은 쓰던 것을 그대로 씁니다.
계측 사각지대 회전기기 베어링, 물탱크 하부, 옥외 판넬, 창고처럼 배선이 어려운 곳의 데이터가 비어 있습니다. 비가시 환경에서도 장거리 무선으로 전송되므로, 그동안 못 보던 지점을 계측점으로 편입할 수 있습니다.

Modbus를 접점으로 삼는 이유

Modbus는 감시용 상위 컴퓨터와 원격 단말(RTU)을 연결하기 위해 만들어진 개방형 산업 프로토콜로, SCADA 계통에서 오랫동안 표준처럼 쓰여 왔습니다. 하나의 유선 네트워크에 약 247대의 장치를 연결할 수 있고, 국내에 설치된 PLC · BMS · HMI · DCS 대부분이 별도 개발 없이 Modbus 마스터로 동작합니다.

즉 게이트웨이가 Modbus 슬레이브 역할을 맡는 순간, 무선센서 데이터는 상위 시스템 입장에서 기존에 읽던 다른 계측기와 구분되지 않는 하나의 레지스터 값이 됩니다. 드라이버 개발도, 미들웨어도 필요 없습니다.

각 구성요소의 역할

① 무선센서 (ALTA)

  • 배터리로 동작하며 설정된 주기마다 측정값을 게이트웨이로 전송합니다.
  • 900MHz 주파수 도약 확산 대역(FHSS) 방식이며, 868 · 433MHz 대역도 지원합니다.
  • 센서 데이터는 Encrypt-RF® 보안(키 교환 + AES-128)으로 암호화되어 전송됩니다.
  • 본체 측면 스티커에 ID와 SC(Security Code)가 인쇄되어 있으며, 게이트웨이 등록 시 이 두 값을 사용합니다.

② 게이트웨이

  • 여러 센서의 최신 값을 내부 레지스터 테이블에 유지하는 데이터 집중기(Data Concentrator)입니다.
  • 상위 시스템의 Modbus 요청이 오면 해당 주소의 값을 응답합니다. 즉 게이트웨이는 슬레이브입니다.
  • 클라우드 플랫폼(iMonnit)을 병행할 수도 있고, 로컬 Modbus 전용으로만 운용할 수도 있습니다.

③ 상위 시스템

  • 기존 PLC · BMS · SCADA · HMI가 Modbus 마스터로서 게이트웨이를 주기적으로 폴링합니다.
  • 추가되는 작업은 레지스터 주소 매핑과 스케일 변환뿐입니다.
설계 시 유의 게이트웨이는 수신한 마지막 값을 보관합니다. 센서 전송 주기(예: 1분)보다 짧은 간격으로 폴링해도 값은 갱신되지 않습니다. 값이 언제 갱신된 것인지는 레지스터에 함께 제공되는 Data Age(마지막 수신 후 경과 초)로 판단합니다.

선택 판단 흐름

  1. 상위 시스템의 통신 포트를 확인합니다. 이더넷 포트로 Modbus TCP를 받고 있다면 이더넷 게이트웨이입니다.
  2. RS-485 데이지체인이 이미 있고 여유 노드가 있다면 시리얼 모드버스 게이트웨이가 배선 재활용 면에서 유리합니다.
  3. 센서 수가 50대를 넘어갈 계획이라면 이더넷 게이트웨이를 권장합니다. 시리얼은 게이트웨이당 50대가 상한입니다.
  4. 설치 위치가 옥외 · 분진 · 습기 환경이라면 IP65 함체를 갖춘 시리얼 모드버스 게이트웨이가 안전합니다.
필수 확인 — Unlock 여부 이더넷 게이트웨이에서 Modbus TCP를 사용하려면 반드시 Unlock Ethernet Gateway 모델이어야 합니다. 일반 모델은 게이트웨이 설정 화면이 Read Only로 표시되며 Modbus 설정을 변경할 수 없습니다. 구매 단계에서 반드시 확인하시기 바랍니다.

05센서 타입별 데이터 정의

Data 1 ~ Data 8의 의미는 센서 종류에 따라 완전히 달라집니다. 이 장은 실제 Modbus Poll 화면과 같은 시각의 플랫폼 화면을 나란히 놓고, 숫자가 어떻게 실제 값이 되는지 보여줍니다.

온습도 센서 (Application ID 43)

  • 140101 = 692549 — 센서 ID입니다. 40101과 40102 두 칸을 32bit Signed Big-endian으로 읽은 결과이며, 센서 본체 스티커의 ID와 같습니다.
  • 240103 = 43 — Application ID. 43은 온습도 센서를 뜻합니다. 이 값으로 슬롯에 어떤 센서가 붙었는지 프로그램이 스스로 판별할 수 있습니다.
  • 340104 = 24 — Data Age. 마지막 수신 후 24초가 지났다는 뜻입니다. 이 값이 계속 커지기만 하면 통신이 끊긴 것입니다.
  • 440107 = 321 — 배터리 전압. ÷100 하여 3.21V입니다. 2V 이하이면 교체 대상입니다.
  • 540109 = 2291, 40110 = 3955 — 측정값입니다. 두 값 모두 ÷100 하여 온도 22.91℃, 습도 39.55 %RH가 됩니다. 그림 5-2의 플랫폼 표시와 정확히 같습니다.

조도 센서 (Application ID 107) — 스케일 처리 주의

조도는 값의 범위가 넓어 Data 1과 Data 2 두 칸을 합쳐서 해석합니다. 상위 시스템 로직을 짤 때 가장 실수가 잦은 부분이므로 화면 세 장으로 순서대로 보겠습니다.

진동 · G-Force · 기울기(Tilt) · 공기질(PM) 센서

진동 계열(일반 진동, 정밀 진동, G-Force Max/Average), 기울기, 공기질 센서 역시 동일하게 슬롯 시작 주소 기준 +8부터 8개 채널에 측정값이 실립니다. 축별 값, 최대 · 평균값 등 채널 구성이 모델마다 다르므로 해당 센서의 정의 문서를 기준으로 매핑합니다.

어느 슬롯에 무슨 센서인지 헷갈릴 때 각 슬롯의 +0/+1(센서 ID, 32bit Big-endian)과 +2(Application ID)만 읽어보면 즉시 확인할 수 있습니다. 센서 본체 스티커의 ID와 대조하면 슬롯 배치가 그대로 드러납니다.

06게이트웨이 설정 절차

이더넷 게이트웨이 기준 설정 순서입니다. 순서 자체가 중요합니다. 특히 IP 변경은 반드시 마지막이며, Default Server 해제를 빠뜨리면 Modbus 전용 운용이 정상 동작하지 않습니다. 아래 각 단계에는 실제 화면을 함께 실었습니다.

  1. Unlock 게이트웨이인지 확인 Modbus TCP 전송을 위해서는 반드시 Unlock Ethernet Gateway 모델이어야 합니다. 설정 화면에 Read Only 문구가 보이면 Modbus 설정이 불가능합니다.
  2. iMonnit 플랫폼에서 HTTP · Modbus TCP 옵션 활성화 Read Only가 표시되어 수정이 안 될 경우, imonnit.com에 가입 후 게이트웨이를 등록(제품 ID / SC 코드 입력)하고 Settings에서 HTTP 및 Modbus TCP를 활성화합니다. 이 작업은 유동 IP(DHCP) 환경에서 진행해야 하며, 게이트웨이 아이콘이 녹색(활성)이어야 합니다. 설정 반영에 최대 5분이 걸리며, 게이트웨이의 Utility 버튼을 한 번 살짝 누르면 즉시 적용됩니다.
  1. 게이트웨이에 할당된 IP 확인 공유기 · 라우터의 관리자 페이지(보통 기기 뒷면에 http://192.168.xx.1 형태로 표기)에 접속해 DHCP 할당 목록에서 게이트웨이가 받은 IP를 확인합니다.
  1. 웹브라우저로 게이트웨이 설정 페이지 접속 PC와 게이트웨이가 같은 네트워크에 있어야 합니다. 접속 후 Gateway Configuration 영역에 Read Only 문구가 없어야 정상이며, Settings 탭에서 아래 항목을 설정합니다.
  • 1IP Address / Subnet Mask / Default Gateway / DNS Server — 현장에서 지정받은 고정 IP를 입력하는 곳입니다. 다만 이 항목은 맨 마지막에 입력합니다(7단계 참조).
  • 2For DHCP: set all fields to 0.0.0.0 — 유동 IP로 쓰려면 네 칸을 모두 0.0.0.0으로 둡니다. 게이트웨이의 초기 상태가 이것입니다.
  • 3HTTP Interface = Enable — 반드시 Enable이어야 이 설정 페이지에 계속 접속할 수 있습니다.
  • 4Save Changes — 각 탭마다 저장 버튼이 따로 있습니다. 탭을 옮기기 전에 반드시 누릅니다.
  1. Settings → Wireless Network에서 센서 등록 센서 본체 측면 스티커의 ID와 SC 코드를 입력해 등록합니다. 슬롯 1번부터 256번까지 사용할 수 있습니다.
  • 1Device ID — 센서 측면 스티커의 ID를 입력합니다.
  • 2Security Code — 같은 스티커의 SC 코드를 입력합니다. 대소문자를 구분합니다.
  • 3Slot Index [1–256] (Optional) — 여기가 레지스터 주소를 결정합니다. 비워두면 자동 배정되지만, 슬롯 번호를 직접 지정하면 원하는 주소에 센서를 고정할 수 있습니다(슬롯 3 → 40133).
  • 4Add Device — 등록 실행. 등록된 센서는 Status 탭 하단 목록에서 확인됩니다.
  • 5Reform Now — 센서 등록·삭제를 모두 마친 뒤 마지막에 한 번 눌러 센서 리스트를 갱신합니다. 이 버튼을 누르지 않으면 값이 올라오지 않는 경우가 있습니다.

삭제는 아래 Remove Device From Network에 Device ID를 넣고 Remove를 누릅니다. Create Network Backup으로 센서 등록 목록을 파일로 내려받아 두면 게이트웨이 교체 시 그대로 복원할 수 있습니다.

  1. Default Server 비활성화 및 하트비트 조정 모넷 클라우드 플랫폼을 쓰지 않고 게이트웨이의 Modbus TCP만 사용한다면, 이 설정을 반드시 해야 합니다. 연동 실패 원인 1위가 이 항목입니다.
  • 1Default Server = Disable — Modbus 전용으로 운용할 때는 반드시 Disable을 선택합니다. 화면처럼 Disable 쪽에 점이 찍혀 있어야 합니다.
  • 2Server Address = sensorsgateway.com — 기본 서버 주소입니다. Disable 상태에서는 이 주소로 데이터를 보내지 않습니다.
  • 3Heartbeat (Minutes) — 기본 5분에서 1분(1.00)으로 낮추는 것을 권장합니다. 값 갱신이 빨라집니다.
  • 4Save Changes — 저장을 눌러야 반영됩니다.
  1. 마지막에 고정 IP 설정 게이트웨이의 초기 연결 옵션은 DHCP(유동)입니다. 고정 IP 현장에 설치하는 경우, 위 항목을 모두 마친 뒤 맨 마지막에 그림 6-3의 ①에 현장 IP · 서브넷 · 게이트웨이를 입력합니다. IP를 먼저 바꾸면 그 즉시 설정 페이지에 접속할 수 없게 됩니다.
연동이 안 될 때 가장 흔한 원인 3가지 ① Unlock 모델이 아니거나 iMonnit에서 Modbus TCP 옵션이 꺼져 있음 (Read Only 표시)
② Default Server를 Disable하지 않음 (그림 6-5 ①)
③ IP를 먼저 바꾼 뒤 나머지 설정을 하려다 접속이 끊김 — IP는 항상 마지막입니다

설정 페이지에 접속이 안 될 때 — HTTP 인터페이스 강제 활성화

07Modbus Poll로 연동 검증하기

PLC · BMS에 붙이기 전에 PC의 Modbus 마스터 도구로 먼저 값을 확인하는 것을 강력히 권장합니다. 이 단계에서 주소와 스케일을 확정해 두면, 상위 시스템 작업은 매핑만 남습니다. 아래는 Modbus Poll 기준이며, 다른 도구도 항목 이름은 대부분 같습니다.

1단계 — Connection Setup (연결 설정)

  • 1Connection = Modbus TCP/IP — 이더넷 게이트웨이는 이 항목을 선택합니다. 시리얼 게이트웨이라면 Serial Port를 선택하고 아래 Serial Settings를 사용합니다.
  • 2IP Address or Node Name — 게이트웨이에 할당된 IP를 입력합니다(6장 그림 6-2에서 확인한 값).
  • 3Server Port = 502 — Modbus TCP 표준 포트입니다. 기본값 그대로 둡니다.
  • 4OK — 연결합니다. 창 상단에 Err = 0이 유지되면 통신이 정상입니다.

2단계 — Read/Write Definition (읽기 설정)

  • 1Slave ID = 1 — 게이트웨이의 슬레이브 주소입니다.
  • 2Function = 03 Read Holding Registers (4x) — 센서 데이터는 홀딩 레지스터에 있으므로 반드시 03번입니다.
  • 3Address = 101 — 슬롯 1번 센서. 화면 오른쪽에 PLC address = 40101이라고 자동 표시되어 맞게 넣었는지 바로 확인됩니다. 슬롯 2번은 117, 슬롯 3번은 133입니다.
  • 4Quantity = 16 — 센서 1대당 레지스터가 16개이므로 16을 넣습니다.
  • 5Rows = Fit to Quantity — 16줄만 보이게 되어 화면이 깔끔해집니다.
  • 6PLC Addresses (Base 1) 체크 — 체크해야 101 → 40101로 해석됩니다. 이 체크를 빠뜨리면 주소가 한 칸씩 밀립니다.

3단계 — 센서 ID로 슬롯 확인 (32bit 형식 변경)

4단계 — 값이 맞는지 확인하는 순서

  1. 센서 ID 대조그림 7-4처럼 표시된 ID가 센서 본체 스티커의 ID와 같은지 확인합니다. 다르면 슬롯 배치를 잘못 본 것입니다.
  2. Application ID로 센서 종류 확인103번 값이 센서 종류 코드입니다. 43이면 온습도, 4면 누수, 107이면 조도, 138이면 모션 플러스입니다.
  3. 상태 레지스터로 통신 건전성 확인105(동작 상태)가 1인지, 104(Data Age)가 센서 전송 주기 이내인지, 108(신호 세기)이 충분한지, 107(배터리)이 2V를 넘는지 확인합니다.
  4. 측정값과 스케일 확정109부터 순서대로 확인하며 실제 환경값과 비교합니다. 5장의 스케일 규칙(÷100, 조도 합성)을 여기서 확정해 상위 시스템에 반영합니다.
  5. 브라우저 화면으로 교차 검증게이트웨이 IP로 직접 접속하면 등록된 센서 목록과 최신 값이 보입니다. Modbus로 읽은 값과 대조하면 매핑 오류가 즉시 드러납니다.

11자주 묻는 질문 & 제품 사양

기존 PLC 프로그램을 많이 수정해야 하나요?
아니요. 게이트웨이는 표준 Modbus 슬레이브로 동작하므로, 다른 Modbus 계측기를 추가할 때와 동일합니다. 필요한 작업은 레지스터 주소를 태그에 매핑하고, 일부 센서의 스케일(÷100, 조도 합성)을 반영하는 정도입니다.
인터넷 연결 없이 폐쇄망에서도 쓸 수 있나요?
가능합니다. 클라우드 플랫폼을 사용하지 않는 경우 Default Server를 Disable로 설정하고 로컬 Modbus 통신만으로 운용합니다. 다만 최초 Modbus TCP 옵션 활성화 시점에는 iMonnit 접속이 필요할 수 있으므로, 설치 전 사무실 등 인터넷 환경에서 설정을 마친 뒤 현장에 반입하는 것을 권장합니다.
센서 하나가 통신이 끊기면 상위에서 알 수 있나요?
알 수 있습니다. 각 슬롯의 동작 상태 레지스터가 0으로 바뀌고, Data Age가 계속 증가합니다. 이 두 값을 상위 시스템 알람 조건으로 잡아두면 센서 장애를 자동으로 감지합니다.
배터리는 언제 교체하나요?
배터리 전압 레지스터 값을 100으로 나눈 값이 실제 전압입니다. 2V 이하이면 교체 대상으로 판단합니다. 상위 시스템에 예방 알람으로 등록해 두면 순회 점검 없이 관리할 수 있습니다.
센서를 나중에 추가하면 주소가 밀리나요?
밀리지 않습니다. 슬롯 번호에 주소가 고정되어 있으므로, 새 센서를 비어 있는 슬롯에 등록하면 기존 매핑은 그대로 유지됩니다. 등록 시 Slot Index를 직접 지정하면 원하는 주소에 고정할 수 있고, 등록 후에는 Reform Now로 센서 리스트를 갱신하십시오.
온도를 화씨로 받을 수 있나요?
게이트웨이는 섭씨(℃)로만 제공합니다. 화씨가 필요하면 상위 시스템에서 변환 로직을 넣어야 합니다.
게이트웨이를 교체하면 센서를 다시 다 등록해야 하나요?
Settings → Wireless Network의 Create Network Backup으로 등록 목록을 파일로 받아 두면, 새 게이트웨이에서 Restore Network Backup으로 그대로 복원할 수 있습니다. 설치 완료 시점에 한 번 받아 두시길 권합니다.
