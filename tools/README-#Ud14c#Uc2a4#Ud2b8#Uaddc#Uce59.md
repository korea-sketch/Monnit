# 자동 테스트 규칙 — 실제 문의와 섞이지 않게 (2026-09-18)

2026-09-18 에 자동 테스트가 담당자 메일함으로 가짜 접수 10여 건을 보냈습니다.
(회사명 「호스트정밀0」 · 접속 IP `127.0.0.1` · 유입 페이지 `localhost:8888`)
같은 일이 없도록 정한 약속입니다.

## 1. 테스트 계정

| 항목 | 값 |
|---|---|
| 이메일 | `1004@monnit.com` (성함 `조한준`) |
| 표시 | 회사명 앞에 `[테스트]` — 서버가 자동으로 붙입니다 |

`@monnit.com` 주소는 무엇이든 테스트로 봅니다. 업종·경쟁사·무료메일 판정을 확인해야 하는
테스트(`dekist.com` · `samsungbiologics.com` · `gmail.com` 등)는 그 도메인을 그대로 씁니다 —
그 경우에도 접속 IP 와 유입 페이지로 테스트인 것이 걸러집니다.

## 2. 판정은 한곳에서 — `netlify/functions/_istest.mjs`

`ops.mjs` · `_monday.mjs` · `lead.mjs` · `proposal-api.mjs` 가 모두 이 파일 하나를 씁니다.
판정이 갈라지면 「원장에선 빠졌는데 보드에는 남는」 상태가 되고 그게 제일 찾기 어렵습니다.

아래 중 하나라도 맞으면 테스트입니다.

1. 이메일이 `@monnit.com`
2. 접점이 `/ops…` (관제에서 직접 찌른 점검)
3. 회사명·성함·메모에 `test` 또는 `테스트`
4. 접속 IP 가 루프백 (`127.0.0.1` · `::1`)
5. 유입 페이지가 `localhost` · `127.0.0.1` · 사설망(192.168 · 10.x · 172.16~31)
6. 요청 본문에 `test: true`

`test: false` 는 **「실제 접수처럼 다뤄 달라」** 는 뜻입니다. 담당자 알림·원장·먼데이
경로 자체를 검증하는 자동 테스트만 씁니다. 브라우저에서 오는 요청에는 이 값이 없습니다.

## 3. 테스트로 판정되면 어디에도 남지 않습니다

| 항목 | 동작 |
|---|---|
| ops 리드 원장 | 남지 않음 — `leads-test` 로 따로 보관 |
| 먼데이 보드 | 올라가지 않음 |
| 담당자 알림 메일 | 나가지 않음 |
| 발송 대장 · 고객 인사이트 | 섞이지 않음 |
| `/ops/proposals` 목록 | 숨김 (확인하려면 주소 뒤에 `?test=1`) |
| 외부 메일 서비스(StaticForms·Web3Forms) | 개발 주소에서는 키가 비어 호출 자체가 안 됨 |

제안서 생성 · PDF · 고객 화면은 그대로 돌아가므로 테스트 자체는 계속 유효합니다.

## 4. 오탐하지 않습니다

`monnit.co.kr` · `monnit.com.tw` 는 남의 주소, `Testo` 는 실제 센서 회사,
`latest` · `contest` 같은 단어는 `test` 로 보지 않습니다(`\btest\b`).

확인: `node tools/test-separation.mjs` (39건) · `node tools/test-testlead.mjs` (23건)
